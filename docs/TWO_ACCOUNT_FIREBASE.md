# ذُخر — حسابان خاصان ومزامنة Firebase

**الحالة:** تجهيز قواعد الحماية والاختبارات فقط في فرع تطوير. لا توجد بيانات حقيقية على Firebase حتى الآن، ولم تتغير نسخة GitHub Pages.

## القرار المعماري
- مستودع GitHub هو مصدر الكود والإصدارات، وليس مخزن الحركات المالية.
- Firebase Authentication لتسجيل الدخول؛ الحسابان ينشئهما المالك يدوياً (بدون زر إنشاء حساب عام).
- Cloud Firestore لحفظ لقطة مالية منفصلة لكل حساب.
- فقط وثيقتان في مجموعة \`approvedUsers\`، بمعرّفي Firebase Auth UID للحسابين. هذه المجموعة تدار فقط من Firebase Console أو Admin SDK؛ تمنع القواعد الإضافة أو التعديل عبر التطبيق.
- يلتزم كل مستخدم بالمسار \`users/{uid}/private/ledger\` فقط، بعد تأكيد البريد.
- جميع المسارات الأخرى مرفوضة، ولا يسمح باستعراض المستخدمين أو حذف السجل من واجهة العميل.

## نقل البيانات دون خطر
1. احتفظ بفرع GitHub الاحتياطي \`backup/pre-firebase-2026-10-31\`؛ لا تدمجه ولا تحذفه.
2. على الهاتف الذي يحتوي السجل الأصلي: إعدادات ذُخر > نسخة احتياطية JSON. خزّن نسختين خاصتين. **لا ترفع JSON إلى GitHub أو المحادثة.**
3. السجل الأصلي مخزن في \`localStorage\` تحت المفتاح \`mizan-finance-v2\`. لا تغيّر المفتاح ولا تستبدله أثناء اختبار Firebase.
4. السجل التجريبي يستعمل \`mizan-finance-v2-preview\` وهو مستقل.
5. الصور العائلية في IndexedDB منفصلة ولا يتضمنها ملف JSON؛ تبقى محلية ولا تُزامن في المرحلة الأولى.
6. بعد تفعيل الحساب الأول، يكون الاستيراد يدوياً لمرة واحدة، ويتحقق \`FinanceEngine.validate\` من البيانات، ومطابقة عدد الحركات والأرصدة وتفاصيل المحافظ والالتزامات قبل وبعد النقل.
7. لا تُزال النسخة المحلية بعد نجاح الاستيراد. يوقف الانتقال إن كان هناك سجل سحابي سابق ولا يُستبدل تلقائياً.

## إعداد Firebase المستقبلي (لم يُنفّذ بعد)
1. أنشئ مشروع Firebase خاصاً بذُخر من Firebase Console.
2. فعّل Authentication > Email/Password وأنشئ الحسابين يدوياً، مع التحقق من بريديهما.
3. أنشئ Firestore في وضع مغلق قبل إضافة أي بيانات حقيقية. انشر الملف \`firebase/firestore.rules\` بعد اجتياز اختبارات المحاكي.
4. أضف وثيقتين فقط في \`approvedUsers/{uid}\` مع قيمة \`approved: true\`؛ يطابق uid مع Firebase Auth لكل حساب، ولا تنشر UID في ملفات المستودع.
5. إعداد Firebase web config ليس مفتاح إدارة سرياً، لكن لا تحفظ مفاتيح service account أو أسرار الإدارة في المستودع العام.
6. اربط واجهة تسجيل الدخول والمزامنة في فرع التطوير حصراً. لا تفعّلها في \`main\` قبل اجتياز التحقق اليدوي والأمني.

## نموذج البيانات
- \`approvedUsers/{uid}\`: وثيقة سماح، يكتبها المسؤول عبر Console/Admin فقط.
- \`users/{uid}/private/ledger\`: \`schemaVersion: 1\`، \`revision: N\`، \`savedAt: serverTimestamp()\`، \`state: {...}\` وهو كائن الحالة الإصدار 2 الموجود في التطبيق.
- زيادة \`revision\` بواحد إجبارية؛ تُجرى الكتابة السحابية عبر معاملة Firestore لرفض التعارض بدل الكتابة فوق تعديل آخر.
- Firestore transactions لا تعمل أثناء انقطاع الإنترنت؛ تبقى العمليات غير المتزامنة محلياً إلى أن تتوفر الشبكة، ثم تُراجع وتُدمج بعد تحقق المحرك. ممنوع استبدال السجل السحابي آلياً ببيانات قديمة.
- حفظ مستند واحد محدود بسعة Firestore القصوى للمستند (1MiB)، ويجب تقسيم السجل إلى صفحات/حركات مستقلة قبل الاقتراب من الحد.
- قواعد المالك لا تعني تشفيراً من طرف إلى طرف؛ مسؤولو مشروع Firebase ذوو الصلاحيات قد يستطيعون قراءة البيانات.

## اختبار القواعد محلياً
من مجلد \`firebase\`:
\`\`\`bash
npm install
npm run test:rules
\`\`\`
هذا يتطلب Node.js وJava مناسبين للمحاكي. اختباراتنا تتأكد من: السماح للحسابين، رفض حساب ثالث، منع الوصول بينهما، رفض الوصول دون تحقق البريد، منع إضافة عضو، منع الاستعراض والحذف، ومنع القفز بين أرقام المراجعة.

## بوابة السماح بالنشر
- نجاح اختبارات المحاكي، وكذلك تجربة حسابين حقيقيين دون بيانات مالية شخصية.
- التطابق التام بين النسخة المحلية والمستوردة في المحرك المالي.
- اختبار تسجيل الخروج واستبدال الحساب على نفس الجهاز: يجب مسح ذاكرة العرض والكاش الخاص بالمستخدم وعدم عرض بيانات الأول للثاني.
- اختبار تضارب أجهزة متعددة، وانقطاع الشبكة، وإعادة الاتصال، والاستعادة.
- حفظ النسخ الاحتياطية خارج GitHub.
- النشر يكون بعد مراجعة Pull Request؛ لا تعديل على الموقع الحالي تلقائياً.

**ملاحظة:** إخفاء زر التسجيل لا يمنع إنشاء حساب Auth عبر واجهة البرمجة؛ الوثيقتان المحددتان في allow-list هما الحد الفعلي للوصول إلى البيانات. يمكن تعطيل التسجيل الذاتي على مستوى الهوية إذا كانت إعدادات المشروع تدعم ذلك.
