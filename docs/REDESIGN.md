# «وين راحت؟» — التدقيق البنيوي وإعادة البناء

تاريخ: 2026-11-03

## 1. التدقيق البنيوي للإصدار السابق

البرنامج السابق كان أقرب إلى **نظام محاسبة مغلّفات** منه إلى برنامج لمتابعة مصاريف البيت.

| المحور | الوضع السابق | المشكلة |
|---|---|---|
| مبدأ العمل | يجب «تخصيص» المال لمحفظة قبل صرفه. المحرك يرفض المصروف إذا كانت محفظة القسم فارغة | المستخدم يريد أن يسجّل ما صرفه، لا أن يدير قيوداً. الواجهة كانت تموّل المحافظ آلياً في الخلفية لتتجاوز هذا القيد |
| أنواع الحركات | 10 أنواع: دخل، تخصيص، حجز، إلغاء حجز، إرجاع، مصروف، سداد، استقطاع، تحويل محافظ، نقل نقد/بطاقة | 7 منها مفاهيم محاسبية داخلية لا يحتاجها المستخدم |
| المفاهيم | محافظ + أقسام معيشة + بنود شهرية + التزامات + خطط شهرية + دورة راتب + شهر | قوائم متوازية لنفس الفكرة (أين يذهب المال) |
| الدخل | مرحلتان ثابتتان (الحوافز 10–12، الراتب 22–24) لكل منهما صفحة ومعالج | مبني على حالة عمل واحدة، وصعب التعميم |
| الواجهة | وضعان (بسيط 4 صفحات، متقدم 10 صفحات + 4 مسارات مخفية) | صفحات مكررة: مصروف ×2، التزامات ×2، تقارير ×2 |
| الحجم | 90 إجراءً، 32 نافذة، 316KB جافاسكربت، 16 ملف CSS (237KB) فوق بعضها | كل تعديل يمر عبر طبقات متعارضة |
| التخزين | 13 مفتاحاً بثلاثة أسماء تاريخية (ميزان، ذخر، فِرزة) | — |

## 2. مبدأ العمل الجديد: تسجيل مباشر

**سجّل ← شوف وين راحت ← خطّط بالميزانية ← تابع دخلك.**

- **الحساب** (نقد، بطاقة…) يعبّر عن *مكان* المال. رصيده = رصيد البداية + الدخل − المصروف ± التحويلات.
- **الحركة** ثلاثة أنواع فقط: مصروف، دخل، تحويل بين حسابين.
- **الفئة** (بقالة، فواتير، مواصلات…) تعبّر عن *سبب* الصرف، ولها **سقف شهري اختياري**. السقف للمقارنة فقط ولا يحجز مالاً.
- **مصدر الدخل** (الراتب، الحوافز…) له يوم متوقع ومبلغ متوقع اختياري. يظهر تنبيه «لم يُستلم بعد» حتى تسجّله.
- **الشهر المالي** يبدأ من يوم تختاره (1–28)، والتقارير والميزانية تتبعه.
- لا يُمنع تسجيل ما حدث فعلاً: إذا أصبح رصيد حساب سالباً يظهر تنبيه لمراجعة رصيد البداية، بدل رفض التسجيل.

## 3. نموذج البيانات (الإصدار 3)

مفتاح تخزين جديد `weenrahat-v3`. البيانات القديمة تبقى كما هي في مفاتيحها.

```
{ version: 3,
  settings: { name, currency, digits, monthStartDay },
  accounts:      [{ id, name, opening, archived }],
  categories:    [{ id, name, icon, color, budget, archived }],
  incomeSources: [{ id, name, day, amount, accountId, archived }],
  transactions:  [{ id, type: expense|income|transfer, date, amount,
                    accountId, toAccountId?, categoryId?, sourceId?, note }],
  meta: { createdAt, migratedFrom? } }
```

المبالغ أعداد صحيحة بأصغر وحدة للعملة (كما في السابق).

## 4. ترتيب الواجهات

| الوجهة | المحتوى |
|---|---|
| **الرئيسية** | صرفت هذا الشهر ومن أي دخل، المتبقي، وتيرة الصرف، أرصدة الحسابات، حالة مصادر الدخل، «وين راحت فلوسك؟» (أعلى الفئات)، آخر الحركات |
| **الحركات** | بحث، فلاتر النوع والفئة والشهر، الحركات مجمّعة حسب اليوم، الضغط للتعديل أو الحذف |
| **＋ سجّل** (الزر الأوسط) | مصروف / دخل / تحويل في نافذة واحدة: المبلغ، الفئة أو المصدر، الحساب، اليوم، ملاحظة، مع «تراجع» بعد الحفظ |
| **الميزانية** | لكل فئة: السقف، المصروف، المتبقي والحالة. تعديل السقوف وإدارة الفئات |
| **التقارير** | الدخل والمصروف والصافي، توزيع المصروف على الفئات، المقارنة بالشهر السابق، الصرف اليومي، آخر 6 أشهر، تنزيل PDF وCSV |
| **الإعدادات** | الاسم والعملة ويوم بداية الشهر، الحسابات، مصادر الدخل، المظهر، النسخ الاحتياطي والاستعادة، بيانات الإصدار السابق |

## 5. نقل البيانات من الإصدار 2

| الإصدار 2 | الإصدار 3 |
|---|---|
| دخل بملاحظة «رصيد البداية» | رصيد بداية للحساب (ليس دخلاً) |
| دخل | دخل، مع مصدره إن وُجد |
| مصروف | مصروف في فئته (من المحفظة أو قسم المعيشة) |
| سداد التزام | مصروف في فئة «التزامات وأقساط» مع اسم الالتزام في الملاحظة |
| نقل بين النقد والبطاقة | تحويل بين حسابين |
| تخصيص، حجز، إلغاء حجز، إرجاع، تحويل محافظ | لا تُنقل: كانت تغيّر الغرض لا الرصيد |
| استقطاع قبل الإيداع | لا يُنقل: لم يمر بالحساب |
| سقوف أقسام المعيشة | سقف شهري للفئة (من آخر شهر محدد) |
| مصادر الدخل ومواعيدها | مصادر دخل بيوم متوقع |

يتحقق النقل من أن رصيد النقد ورصيد البطاقة بعد النقل يساويان الرصيدين في الإصدار 2، وإلا يتوقف ويترك البيانات القديمة كما هي.
